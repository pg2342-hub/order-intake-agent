Order Intake Agent

Shippers email load requests as PDFs, spreadsheets, forwarded threads and one-line notes. This agent reads each one, applies that shipper's own rules, and either fills in the order for the trucking company's system or hands it to an operator with a note saying why. Pick an email to see what it does.

    Rollout, one shipper at a time

    No shipper goes straight to orders posting on their own. Each account starts in shadow (the agent reads every email, operators still key every order, the two are compared), moves to approve (good orders wait for one click), and reaches auto only when its emails clear the bar. Below is the stage each account's test emails support today.

    How it decides

    1Account

    Code files the email under the shipper by the sender's domain. The model never picks the customer.

    2Read

    Claude reads the email and attachments with that shipper's rules and the facility directory, and returns the order, what kind of request it is, and which fields it is unsure of.

    3Check

    Code holds the order if the reference or weight is not written in the email, a facility is unknown, dates run backwards, the shipper's rule is broken, or it is hazmat, a duplicate, a change or a cancellation.

    4Hand off

    A held order goes to an operator with a short note, written after code has decided, saying what was asked and what to check.

    The shippers' rules

    Each account's rules, as an operator would explain them in discovery. The agent gets them with every email; code re-checks the ones a rule can state exactly.
